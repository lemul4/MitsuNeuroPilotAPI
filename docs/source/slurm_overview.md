(Возможно не работает)

```{note}
Это полностью опциональная функция. Интеграция со SLURM предназначена для пользователей с доступом к HPC-кластерам, которые хотят эффективно масштабировать эксперименты. Вся функциональность также может запускаться локально без SLURM.
```

LEAD включает опциональный минимальный SLURM wrapper для запуска экспериментов на HPC-кластерах. Дизайн opinionated, но он используется в нашем исследовательском workflow и отделен от основной кодовой базы.

## Зачем использовать этот wrapper?

Wrapper закрывает несколько практических задач при запуске ML-экспериментов на HPC-кластерах:

- **Упрощенный запуск**: отправка training runs, оценок и перезапусков по нескольким seed без ручной отправки задач
- **Единая организация**: генерация согласованных имен для SLURM-задач, WandB-экспериментов и выходных директорий
- **Параллельное выполнение**: одновременный запуск нескольких задач обучения и оценки
- **Совместимость с несколькими кластерами**: поддержка разных кластеров с разными именами partition

Основной принцип: **один эксперимент = один bash-скрипт**. Каждый скрипт версионируется для воспроизводимости.

## Как это работает: полный пример

Ниже типичный workflow, начинающийся с предобучения модели с нуля.

### Шаг 1: создание первого скрипта обучения

Минимальный скрипт предобучения из [slurm/experiments/001_example/000_pretrain1_0.sh](https://github.com/kesai-labs/lead/blob/main/slurm/experiments/001_example/000_pretrain1_0.sh):

```{code-block} bash
:linenos:

#!/usr/bin/bash

source slurm/init.sh

export LEAD_TRAINING_CONFIG="$LEAD_TRAINING_CONFIG image_architecture=regnety_032 lidar_architecture=regnety_032"

train --cpus-per-task=32 --partition=a100-galvani --time=3-00:00:00 --gres=gpu:4
```

**Соглашение об именах**: скрипты следуют шаблону `slurm/experiments/<exp_id>_<exp_name>/<step_id>_<step_name>_<seed>.sh`. Это создает иерархию: эксперименты содержат несколько шагов (предобучение, fine-tuning, оценка), каждый из которых может запускаться с разными random seed.

**Разбор по строкам**:

1. **Строка 1**: стандартный заголовок bash-скрипта
2. **Строка 3**: подключает [slurm/init.sh](https://github.com/kesai-labs/lead/blob/main/slurm/init.sh), который настраивает переменные окружения и определяет вспомогательные функции вроде `train`
3. **Строка 5**: настраивает архитектуру модели через переменные окружения (соответствует опциям в [lead/training/config_training.py](https://github.com/kesai-labs/lead/blob/main/lead/training/config_training.py))
4. **Строка 7**: запускает обучение с параметрами SLURM (CPU, GPU, лимит времени, имя partition)

### Шаг 2: запуск эксперимента

Выполните скрипт:

```bash
bash slurm/experiments/001_example/000_pretrain1_0.sh
```

Wrapper создает организованную выходную директорию:

```bash
outputs/training/001_example/000_pretrain1_0/<year><month><day>_<hour><minute><second>
```

Логи, checkpoints и метрики сохраняются в этой директории с timestamp для сравнения и воспроизводимости.
