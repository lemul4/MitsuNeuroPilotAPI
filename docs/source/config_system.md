# Система конфигурации

Многие значения конфигурации в нашей системе взаимозависимы и должны вычисляться динамически на основе других настроек (например, количество камер зависит от целевого датасета, а размеры BEV-сетки зависят от границ области планирования). Хотя фреймворки вроде Hydra дают мощные возможности композиции, для нашего сценария полезнее простота и прямолинейность Python-классов с вычисляемыми свойствами.

На этой странице объясняется, как работает наша система конфигурации: иерархия переопределений, структура наследования конфигов и система динамических свойств.

> **Примечание**: Эта документация в первую очередь актуальна, если вы хотите обучать модели. Для одной только оценки обычно достаточно конфигураций по умолчанию.

## Переопределение конфигураций по умолчанию

Конфигурации могут загружаться из нескольких источников с четкой иерархией приоритетов от самого высокого к самому низкому. Источник с более высоким приоритетом всегда побеждает.

1. **Аргументы CLI** (через `load_from_args`)
2. **Переменные окружения** (через `load_from_environment`)
3. **Файлы конфигурации** (через `load_from_file`)
4. **Значения по умолчанию в классе** (определены в классе)

Например, рассмотрим конфигурацию `batch_size`:
- Если значение по умолчанию в классе равно `64`
- И вы загружаете файл конфигурации, где указано `"batch_size": 32`, то `batch_size` становится `32`
- Но если вы также задаете `LEAD_TRAINING_CONFIG="batch_size=48"`, то `batch_size` становится `48`
- Однако если передать `batch_size=128` через CLI, итоговый `batch_size` будет `128` (CLI имеет самый высокий приоритет)

Разные классы конфигурации используют разные комбинации загрузки в зависимости от сценария применения:

| Класс конфигурации | Методы загрузки | Порядок приоритета | Причина |
|-------------|----------------|----------------|--------|
| `TrainingConfig` | `load_from_environment` + `load_from_args` | Args > Environment | Скрипты обучения поддерживают и CLI-аргументы (самый высокий приоритет), и переменные окружения |
| `ClosedLoopConfig` | только `load_from_environment` | только Environment | Запуски оценки CARLA запрещают прямой доступ через CLI |
| `OpenLoopConfig` | только `load_from_environment` | только Environment | Запуски оценки CARLA запрещают прямой доступ через CLI |
| `ExpertConfig` | только `load_from_environment` | только Environment | Запуски оценки CARLA запрещают прямой доступ через CLI |

**Примечание:** `TrainingConfig` уникален тем, что поддерживает **и** переменные окружения, **и** CLI-аргументы, причем CLI-аргументы имеют приоритет. Это дает гибкую настройку во время обучения, но при необходимости сохраняет поддержку конфигурации через окружение.

Опция `load_from_file` в основном используется для продолжения прерванного обучения или fine-tuning,
когда нужно загрузить полную конфигурацию из предыдущего эксперимента.

## Иерархия конфигов

Разным сценариям использования требуется только подмножество всех возможных настроек. Особенно полезен сценарий, когда
мы обучаем модель на одной калибровке сенсоров и параллельно собираем данные с другой калибровкой сенсоров.

```
BaseConfig (common/config_base.py)
├── Конфигурация камер и сенсоров
├── Механизмы загрузки (файл, окружение, CLI)

TrainingConfig (training/config_training.py)
├── Наследуется от BaseConfig
├── Свойства, зависящие от датасета
├── Настройки архитектуры модели
├── Гиперпараметры обучения

ExpertConfig (expert/config_expert.py)
├── Наследуется от BaseConfig
├── Свойства, зависящие от датасета
├── Настройки логики эксперта

OpenLoopConfig (inference/config_open_loop.py)
├── Наследуется от BaseConfig
└── Настройки офлайн-оценки

ClosedLoopConfig (inference/config_closed_loop.py)
├── Наследуется от OpenLoopConfig
└── Настройки онлайн-симуляции CARLA
```

## Система динамических свойств

Мы используем два типа динамических свойств:

**1. Стандартное `@property`**

Используется для вычисляемых значений, которые нельзя переопределять:

```python
@property
def num_used_cameras(self):
    """Computed from the used_cameras list."""
    return sum(int(use) for use in self.used_cameras)
```

**2. Пользовательское `@overridable_property`**

Эти свойства могут переопределяться пользователями. Например, количество эпох зависит от используемого датасета:

```python
@overridable_property
def epochs(self):
    """Default epochs by dataset, but can be overridden."""
    if self.carla_leaderboard_mode:
        return 31
    if self.target_dataset == TargetDataset.NAVSIM_4CAMERAS:
        return 61
    return 20
```

Это можно переопределить, задав `epochs=61` в CLI.
