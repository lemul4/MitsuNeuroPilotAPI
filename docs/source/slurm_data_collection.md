```{note}

```

Перед обучением моделей требуется собрать данные. Система сбора данных оркестрирует задачи симуляции CARLA на кластере, управляя отправкой задач, мониторингом сбоев и автоматической повторной отправкой упавших маршрутов.

## Подготовка запуска сбора данных

Настройте следующие параметры в [slurm/data_collection/collect_data.py](https://github.com/kesai-labs/lead/blob/main/slurm/data_collection/collect_data.py):

- **`repetitions`**: сколько раз запускать каждый маршрут с разными random seed (для разнообразия данных)
- **`partitions`**: имена partition кластера (например, `gpu-2080ti`, `a100-galvani`)
- **`dataset_name`**: описательное имя датасета (например, `carla_leaderboard2_train`)

**Использование формата данных Py123D:**

Флаг `--py123d` включает сбор в формате Py123D, который предоставляет унифицированное представление данных, совместимое с другими крупными датасетами автономного вождения. Этот формат полезен для:
- Кросс-датасетного обучения и оценки
- Объединения данных CARLA с реальными датасетами
- Стандартизированных pipeline обработки данных

При использовании `--py123d`:
- Экспертный агент автоматически переключается на `expert_py123d.py`
- Имя датасета становится `carla_leaderboard2_py123d`

Процессом сбора управляют еще два файла конфигурации:

- [slurm/configs/max_num_parallel_jobs_collect_data.txt](https://github.com/kesai-labs/lead/blob/main/slurm/configs/max_num_parallel_jobs_collect_data.txt): максимальное число параллельных задач (настраивайте в соответствии с емкостью кластера)
- [slurm/configs/max_sleep.txt](https://github.com/kesai-labs/lead/blob/main/slurm/configs/max_sleep.txt): задержка между запуском сервера CARLA и Python-клиента (предотвращает проблемы тайминга соединения)

## Запуск сбора

Войдите на login node кластера и запустите сбор:

```bash
# Стандартный формат LEAD (по умолчанию)
python3 slurm/data_collection/collect_data.py

# Формат Py123D для кросс-датасетной совместимости
python3 slurm/data_collection/collect_data.py --py123d

# Опционально: указать пользовательские папки маршрутов и данных
python3 slurm/data_collection/collect_data.py \
  --route_folder data/custom_routes \
  --root_folder /scratch/datasets/

# Py123D с пользовательскими папками
python3 slurm/data_collection/collect_data.py \
  --py123d \
  --route_folder data/custom_routes \
  --root_folder /scratch/datasets/
```

Скрипт создает структурированную выходную директорию:

```
data/carla_leaderboard2
├── data     # Хранилище данных сенсоров
├── results  # JSON-файлы результатов
├── scripts  # Сгенерированные SLURM bash-скрипты
├── stderr   # Логи stderr SLURM
└── stdout   # Логи stdout SLURM
```

**Примечание**: Сбор данных может занимать до 2 дней на 90 GPU для 9000 маршрутов. Запускайте скрипт внутри `screen` или `tmux`, чтобы предотвратить прерывание при разрыве SSH-соединения.

## Мониторинг сбора

Проверяйте прогресс сбора и выявляйте сбои:

```bash
python3 slurm/data_collection/print_collect_data_progress.py
```

Обновите переменную `root` в скрипте так, чтобы она указывала на директорию с вашими данными.

```{note}
Доля сбоев ниже 10% типична и в основном вызвана падениями симуляции или аппаратными проблемами.
Некоторые типы сценариев могут показывать более высокую долю сбоев (около 50%), что указывает на ограничения политики эксперта в этих конкретных ситуациях. Это ожидаемое поведение: пока для большинства сценариев доля сбоев ниже 10%, качество датасета остается достаточным для обучения.
```

## Очистка неудачных маршрутов

Удалите поврежденные или неполные данные после завершения сбора:

```bash
python3 slurm/data_collection/delete_failed_routes.py
```

Это отфильтрует датасет, оставив только успешно собранные маршруты.

```{warning}
Этот шаг очистки опционален. Pipeline обучения автоматически фильтрует неудачные маршруты.
Изучение неудачных маршрутов может выявить biases политики эксперта и проблемы сбора данных.
```
